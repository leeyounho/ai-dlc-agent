# 평가 보고서에 실행 환경을 기록하고 비교 시 차이를 표시한다

상태: 자기 적용을 위한 로컬 Issue 초안. 미접수·미승인·미구현이며 실제 GitHub에 게시하지 않았다.

## 배경과 목적

현재 로컬 평가 보고서는 Agent/source/suite digest를 기록하지만 Python과 OS 정보를 기록하지 않는다. 서로 다른 환경의 결과를 비교할 때 동일 조건의 실행인지 판단할 근거가 부족하다.

평가 결과의 재현성과 비교 가능성을 높이기 위해 실행 환경을 기록하고, 비교 결과에 환경 차이를 명시한다.

## 범위

- Python 구현체·정확한 버전, OS 계열·release, machine architecture를 허용된 필드로 기록.
- 환경 변수·hostname·사용자 이름·전체 경로·credential을 수집하거나 저장하지 않음.
- JSON/Markdown 보고서와 CLI의 비교 결과에 필요한 환경 정보를 표시.
- 기존 report schema의 읽기/마이그레이션 방식을 명시. 이전 보고서의 환경을 현재 머신 정보로 추정하지 않음.
- 네트워크 호출·실제 모델 연결·운영 적합 판정 기능은 이 Issue의 범위에 포함하지 않음.

## 인수 조건

1. 같은 source/suite에서 만들어진 보고서에도 실제 실행 당시의 환경 정보가 저장된다.
2. 환경이 다른 결과는 환경 차이를 보여주며, 환경이 같다고 단정하거나 성능 우열을 자동 결론 내리지 않는다.
3. 같은 suite의 사례별 pass/fail 비교는 계속 가능하되 환경 차이와 미확인을 함께 표시한다.
4. 구버전 보고서의 환경은 unknown으로 표시하거나 명시적인 호환성 오류를 반환한다. 선택한 정책을 문서에 기록한다.
5. synthetic fixture로 동일/상이/미확인 환경과 schema 오류를 검증한다. 실제 다른 OS나 외부 서비스 접근을 테스트의 전제 조건으로 삼지 않는다.
6. 기존 unittest와 로컬 평가가 통과하고 `eligible_for_release=false` 의미가 유지된다.
7. PR은 선택한 보고서 schema·구버전 처리·비교 동작·실제 검증 결과를 완결된 문서로 설명한다.

## 변경 후보

- ai_dlc/evaluation/runner.py의 manifest·report 읽기/표시·비교.
- 필요 시 독립된 환경 metadata DTO/helper.
- tests의 보고서 호환성·비교 사례와 README 설명.

Agent가 승인 없이 평가 기대값을 바꿔 성공으로 만들지 않도록 기존 회귀 세트는 평가자 쪽에서 별도로 유지한다. 실제 구현 방식과 파일은 요구사항 정리·설계 과정에서 조정할 수 있다.
